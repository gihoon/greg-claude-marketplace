# do-hot-pdf — HTML → PDF 렌더

이미 만들어진 HTML을 **배포 가능한 PDF로 굳히는** 스킬. 내용은 만들지 않는다. 내용이 없으면 먼저 `/do-hot-report`(1p 요약서)나 `/do-hot-pt`(IR 덱)로 HTML을 만든다.

## 트리거

`/do-hot-pdf` 또는 "PDF로 뽑아줘 · 내보내줘 · 인쇄본으로 · 첨부용으로"

## 두 가지 모드 (입력을 보고 자동 판별)

| 입력 | 판별 | 페이지 |
|---|---|---|
| `/do-hot-report` 결과 — `.sheet` | 기본 | A4 세로 210×297mm, 시트 1장 = 1페이지 |
| `/do-hot-pt` 결과 — `.canvas` | `class="canvas` 포함 시 | 가로 254×142.875mm(=960×540px), 슬라이드 1장 = 1페이지 |

덱은 스크롤 스냅·`transform: scale()`을 쓰기 때문에 그대로 인쇄하면 첫 슬라이드만 나온다. `build.sh`가 **임시 사본에 인쇄 CSS를 주입해서** 스냅·스케일을 풀고 각 슬라이드를 페이지로 끊는다. **원본 HTML은 수정하지 않는다.**

## 실행

```bash
bash ~/.claude/skills/do-hot-pdf/assets/build.sh <input.html> [out.pdf]
# 출력 파일명 생략 시 <input>.pdf
# Chrome 경로가 다르면: CHROME="/path/to/Chrome" bash build.sh ...
```

스크립트가 모드와 결과 페이지 수를 출력한다.

## 검증 (건너뛰지 않는다)

렌더는 조용히 망가진다. 페이지 수만 보고 끝내지 않는다.

1. **페이지 수 확인** — 스크립트 출력값이 기대와 맞는가. 1p 요약서인데 2페이지면 내용이 넘친 것이고, 덱인데 1페이지면 인쇄 CSS가 안 먹은 것이다.
2. **눈으로 본다** — PDF 페이지를 이미지로 읽어 확인한다. 특히:
   - 문서: 마지막 문단·표 마지막 행이 잘리지 않았는지, 아래 여백이 과하지 않은지
   - 덱: 배경색이 페이지 전체를 덮는지(흰 띠 금지), 푸터·페이지번호가 살아 있는지, 제목이 잘리지 않았는지
3. **폰트 확인** — Pretendard CDN이라 네트워크가 없으면 시스템 폰트로 대체되어 줄바꿈이 통째로 달라진다. 글자가 어색하면 폰트부터 의심한다.

## 넘칠 때 (고치는 곳은 HTML이지 PDF가 아니다)

- 1p 요약서가 2페이지가 됐다 → `/do-hot-report`로 돌아가 **문장을 줄인다.** 폰트·여백을 줄이지 않는다.
- 덱 슬라이드가 잘렸다 → `/do-hot-pt`로 돌아가 **글자 수를 줄인다.**
- `build.sh`의 인쇄 CSS를 늘려 억지로 맞추지 않는다. 형식이 아니라 내용을 줄이는 게 이 계열 스킬의 규칙이다.

## 자산

- `assets/build.sh` — 모드 판별 + Chrome headless 렌더 + 페이지 수 출력
