# Index — 볼트 인덱스 관리 스킬

> "LLM이 인덱스 파일과 모든 문서의 간략한 요약을 자동으로 관리해 주었다." — Andrej Karpathy

## 개요

Karpathy가 "RAG 없이 충분하다"고 말할 수 있었던 비밀은 **자동 관리되는 인덱스 파일**입니다. 이 스킬은 제텔카스텐의 프론트매터 인덱스 시스템(`claim`, `links`, `cluster`)을 활용하여 볼트 전체의 인덱스를 자동 생성하고 갱신합니다.

## 트리거

사용자가 `/do-index` 또는 `/인덱스`를 입력했을 때 실행합니다.

## 인덱스 구조

`_index/` 폴더에 3종류의 인덱스를 생성합니다:

### 1. VAULT_INDEX.md — 전체 인덱스

볼트의 모든 영구노트와 문헌노트의 프론트매터를 한 파일에 압축합니다.

```markdown
# Vault Index
> 자동 생성됨. 수동 편집 금지. `/do-index`로 갱신.

## 클러스터: 글쓰기와 창작
| ID | Claim | Tags | Links |
|----|-------|------|-------|
| 1 | 자발적 시간 압박은 선택지를 줄여... | 글쓰기, 완벽주의 | 1a, 1b |
| 1a | 사고는 글쓰기의 전제가 아니라... | 글쓰기, 사고 | 1, 1b, 1a1, 1a2 |

## 클러스터: AI와 인간의 관계
| ID | Claim | Tags | Links |
|----|-------|------|-------|
| 2 | AI의 무한한 속도가 역설적으로... | AI, 번아웃 | 1, 1a, 2a, 2b, 2c |
```

이 파일 하나만 읽으면 볼트 전체의 지식 구조를 파악할 수 있습니다. `/do-query` 스킬의 1단계 검색에서 이 파일을 사용합니다.

### 2. CLUSTER_MAP.md — 클러스터 관계도

클러스터 간 교차 연결을 시각화합니다.

```markdown
# Cluster Map

## 글쓰기와 창작 (노트 6개)
- ↔️ AI와 인간의 관계: 3개 교차 연결
- ↔️ 인간의 주체성과 회복: 2개 교차 연결

## AI와 인간의 관계 (노트 5개)
- ↔️ 글쓰기와 창작: 3개 교차 연결
- ↔️ 도구와 플랫폼: 2개 교차 연결
```

### 3. GRAPH.md — 연결 그래프 (텍스트)

모든 노트 간 연결을 flat list로 기록합니다.

```markdown
# Connection Graph

1 → 1a, 1b
1a → 1, 1b, 1a1, 1a2
1a1 → 1a, 1, 2b, 2
1a2 → 1a, 1a1, 2b1
2 → 1, 1a, 2a, 2b, 2c
...
```

## 실행 프로세스

### Step 1: 전체 스캔

`2 Permanent/`와 `1 Literature/`의 모든 `.md` 파일에서 프론트매터를 추출합니다.

### Step 2: 인덱스 생성·갱신

3개 인덱스 파일을 생성하거나, 이미 존재하면 갱신합니다.
- 기존 인덱스와 비교하여 변경된 부분만 업데이트
- 새 노트 추가, 삭제된 노트 제거, 변경된 프론트매터 반영

### Step 3: 통계 보고

```
📊 인덱스 갱신 완료

노트 현황: 영구노트 11개, 문헌노트 3개
클러스터: 4개 (글쓰기와 창작, AI와 인간의 관계, 도구와 플랫폼, 인간의 주체성과 회복)
연결: 총 28개 (평균 2.5개/노트)
최다 연결 노트: 2. AI는 인간에게 번아웃을 유발한다 (5개)
고립 노트: 0개
```

## 핵심 원칙

1. **자동 생성**: `_index/` 파일은 수동 편집 금지. 항상 `/do-index`로 갱신
2. **프론트매터가 진실**: 인덱스는 프론트매터에서 파생. 프론트매터가 틀리면 인덱스도 틀림
3. **경량**: 전체 본문이 아닌 프론트매터만 사용. 노트가 수만 개여도 인덱스는 수십 KB
4. **다른 스킬의 기반**: `/do-query`와 `/do-lint`가 이 인덱스를 활용
