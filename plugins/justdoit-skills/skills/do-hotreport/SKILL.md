# do-hotreport — 네이비 러스트 A4 1p 요약서

사업·제품·투자 내용을 **A4 한 장에 다 넣는 요약서**로 만든다. `HOTPLX_TIPS_1p.docx`에서 추출한 디자인 시스템. `/do-hotpt`(IR 덱)와 같은 색 팔레트의 문서판.

## 트리거

`/do-hotreport` 또는 TIPS 요약·투자 요약·1p 브리프·사업 개요 한 장 요청

## 언제 쓰나

- 심사역·기관이 **먼저 읽는 한 장** — 덱을 열기 전에 전체를 파악해야 할 때
- (구분) `/do-hotpt` = 16:9 IR 덱 · **`/do-hotreport` = A4 1p 요약서** · `/do-report` = 표지·목차 있는 다페이지 기관 리포트 · `/do-hotpdf` = 위 결과물의 PDF 렌더

## 형식 (핵심 — 임의 변경 금지)

- **`.sheet` = A4 실치수 210×297mm + `overflow:hidden`**: 시트 1장이 PDF 1페이지다. 여백 `10.9 / 12 / 9.2mm`(원본 docx 그대로). **넘치면 잘린다.**
- **1페이지가 기본**: 한 장에 끝내는 것이 이 형식의 긴장감이다. 정말 안 들어가면 `.sheet`를 하나 더 추가한다(2~3장까지 허용).
- **밀도 규칙**: 본문 9pt / 줄간 1.19 / 문단 간격 2.4pt. 여백이 아니라 정보로 페이지를 채운다.
- **색은 세 개뿐**: 네이비 `#1B2A4A`(제목·섹션바·표헤더·정량 라벨) · 러스트 `#9C4A34`(항목 라벨·강조 수치) · 본문 `#2B2F36`. 부제·각주만 회색 `#6E7681`.
- **섹션바가 리듬을 만든다**: 네이비 배경 + 흰 볼드 8.5pt. 제목만 쓰지 말고 `— 부제`로 논지를 한 번 더 밝힌다.
- 색·치수는 `assets/hot-1p-skeleton.html`의 `<style>`에 정의됨 — **그대로 유지한다.**

## 컴포넌트 (마크업은 스켈레톤 — 복제해서 텍스트만 교체)

| 클래스 | 용도 | 형태 |
|---|---|---|
| `h1` + `.meta` | 문서 머리 | 13pt 볼드 네이비 + 8pt 회색 성격표기 |
| `.tagline` | 전체를 한 문장으로 | 9.5pt 볼드 러스트, 아래 네이비 실선 |
| `.secbar` | 섹션 시작 | 네이비 바 + 흰 볼드. 앞에 공백 2칸 |
| `.l` | 정량·설계 라벨 | 볼드 네이비 (정의·설계·수치·로드맵) |
| `.lr` | 나열·논점 라벨 | 볼드 러스트 (①②③④·과제 n·경쟁·기반) |
| `table` | 구조를 표로 | 네이비 헤더 + 줄무늬 `#F1F3F7` + `#D7DBE2` 테두리, 7.5pt |
| `.hot` | 강조 수치 | 볼드 러스트. **한 페이지에 두세 개까지** |
| `b` | 문장 속 핵심구 | 볼드(색 없음) |
| `.fine` | 가정·단서 | 이탤릭 회색. 수치 문단 끝에 붙인다 |

문단 간격은 `p`(기본) · `p.tight`(①②③ 나열처럼 붙일 때) · `p.gap`(섹션 마지막) 셋으로만 조절한다.

## 빌드 절차

1. **스켈레톤 복사**: `assets/hot-1p-skeleton.html`을 작업 위치로 복사.
2. **`<style>`·`<script>`·`.sheet`는 건드리지 않는다.** (형식의 핵심)
3. 머리 → 태그라인 → 정의 → 섹션 4~6개 순으로 채운다. **섹션 하나 = 논점 하나.**
4. 표는 한 페이지에 하나까지. 3열(축 / 대상·과금 / 핵심)이 기본형이다.
5. **저장**: `<주제>_1p.html`.
6. **렌더 검증** — 눈으로 본다. 오라클 없이 "잘 나왔다"고 하지 않는다:
   ```bash
   CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
   "$CHROME" --headless=new --disable-gpu --window-size=830,1180 \
     --screenshot=out.png "file://$PWD/<주제>_1p.html"
   ```
   PDF로 넘기려면 `/do-hotpdf`.

## 넘침·여백 판정 (이 형식의 유일한 실패 모드)

스켈레톤의 `<script>`가 넘치는 시트에 **빨간 테두리**를 두른다(화면에서만, 인쇄에는 안 나옴). 콘솔에 초과 px도 찍힌다.

- **넘칠 때 → 문장을 줄인다.** 폰트·여백·줄간을 줄이지 않는다. 밀도는 이미 한계값이다.
- **아래가 30% 넘게 비면 → 내용이 부족한 것.** 섹션이나 표 행을 늘린다. 폰트를 키워 채우지 않는다.
- 검증은 스크린샷과 PDF 페이지 수 둘 다로 한다. `scrollHeight`만 믿지 않는다.

## 원칙

- 라벨 + 한 줄. 한 항목이 두 줄을 넘으면 문장이 아니라 내용이 정리가 안 된 것이다.
- 검증된 숫자와 목표 숫자를 섞지 않는다. 목표에는 반드시 `.fine`으로 단서를 단다.
- 경쟁 서술은 "무엇이 다른지"로 쓴다. 상대 기능 부재를 주장하지 않는다.
- 인터넷 필요(Pretendard CDN). 오프라인 배포는 woff2 로컬 임베드.
