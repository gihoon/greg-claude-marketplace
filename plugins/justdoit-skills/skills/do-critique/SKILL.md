# Critique — 적대적 검증 (Red-Team)

명세·기획·사업 노트가 '확정'으로 넘어가기 전에, 그 안의 가정과 수치를 적대적으로 두들긴다. `/do-sharpen`이 아이디어를 날카롭게 다듬는다면, `/do-critique`는 **그 날이 진짜인지 반증한다.**

## 트리거

`/do-critique` 또는 `/검증`, `/레드팀`, "구멍 찾아줘", "이거 진짜 될까", "반박해줘"

## 언제 쓰나

- `/do-sharpen` 명세·`/do-productify` 로드맵을 **확정하기 전**
- 사업 노트(IR 요약·기획서)의 수치·가정이 **실적인지 목표치인지 흐릴 때**
- 파이프라인 위치: **`/do-sharpen`(명세) → `/do-critique`(검증) → `/do-productify`(로드맵)**. 확정 전 관문.

## 핵심 원칙 (칭찬 금지)

- **반증 우선** — 기본값은 "성립하지 않는다". 근거로 뒤집어야 통과한다.
- **구체적 실패 시나리오** — "리스크 있음"이 아니라 *"입력 X·상황 Y → 결과 Z로 깨진다"*.
- **수치 정직성** — 목표치와 실적을 구분한다. 근거(표본·계산식·출처) 없는 낙관은 표시한다.
- **급소만 본다** — critique는 강점을 다루지 않는다. 강점은 명세·노트가 이미 담았다.

## 입력

- 명세/기획 `.md` 경로 · permanent 노트 · Notion URL · 평문 텍스트

## 프로세스

### Step 1 — 대상 로드 & 검증 대상 추출

입력을 읽고 두들길 것을 목록화한다: ① 핵심 주장 ② 수치·트랙션 ③ 암묵 가정("당연히 될 것") ④ 시장·경쟁 전제 ⑤ 실행 계획.

### Step 2 — 다차원 적대 검증 (병렬)

각 렌즈는 독립적으로 *"이걸 어떻게 반증하나"*를 묻는다. 대상이 크면 서브에이전트 병렬 실행:

| 렌즈 | 묻는 것 |
|------|---------|
| **가정** | 검증 안 된 전제는? 무너지면 뭐가 같이 무너지나 |
| **수치** | 목표치 vs 실적? 근거·표본·계산식이 있나. 전환율·유지율 가정의 출처 |
| **시장·경쟁** | 대체재·기성 서비스는? 차별점이 실제 전환(결제)을 만드나 |
| **논리·일관성** | 섹션 간 모순·비약·순환 논리 |
| **실행·리스크** | 진짜 game stopper는? 자원·규제·타이밍·핵심 인물/데이터 의존 |

### Step 3 — 발견 정리

각 발견에 셋을 붙인다:
- **심각도** — 🔴 치명(확정 불가) · 🟡 주의(보강 필요) · 🟢 경미
- **반증 시나리오** — 구체 입력 → 결과
- **보강 액션** — 무엇을 검증/추가하면 이 급소가 닫히나

### Step 4 — 종합 판정

- **확정 가능한가** — 🔴가 하나라도 있으면 *"확정 불가 — 아래를 먼저"*. 없으면 *"조건부 확정"*.
- **Top 3 급소** + 각각의 다음 액션 1줄.

## 출력

크리틱 리포트 — 대상이 볼트 노트면 그 옆/하위에, 아니면 로컬 `./{대상}-critique.md`:

```markdown
# {대상} — 크리틱 리포트
**확정 판정**: 🔴 확정 불가 / 🟡 조건부 확정 / 🟢 확정 가능
**Top 3 급소**: 1) … 2) … 3) …

---
## 🔴 치명 ({N})
- **[가정]** {발견} — 반증: {입력→결과} → 보강: {액션}

## 🟡 주의 ({N})
- **[수치]** {발견} — 반증: {…} → 보강: {…}

## 🟢 경미 ({N})
- …
```

## /do-sharpen·/do-productify와의 관계

- `/do-sharpen` 명세가 나오면 → `/do-critique`로 반증 → 통과분만 `/do-productify`로.
- 사업 노트라면 → `/do-critique`로 급소를 뽑아 노트의 **리스크 섹션을 실전화**한다.

> **"확정은 칭찬이 아니라, 반증을 통과한 상태다."**
